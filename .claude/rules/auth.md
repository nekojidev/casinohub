# Auth Service

Регистрация, JWT, ежедневный бонус. Не начинай этот сервис, пока Wallet не пройден до конца — Auth нужен только когда Wallet готов принимать реального пользователя.

## Конвенции

- Пароли — только `bcrypt` (или `argon2`, обсуди разницу перед выбором), никогда не хранить plaintext даже "временно".
- JWT — access token короткоживущий (15 мин), refresh token отдельно, ротация при обновлении.
- `AuthGuard`/`Strategy` через `@nestjs/passport` — стандартный Nest-паттерн, не изобретать свой.
- Событие `user.registered` в RabbitMQ должно создавать кошелёк в Wallet Service асинхронно — но синхронный fallback (прямой вызов при регистрации) обсудить как альтернативу, прежде чем писать асинхронную версию.
- Ежедневный бонус — идемпотентность через Redis-ключ `bonus:claimed:{userId}:{date}` с TTL до конца дня.

## Тесты

- Unit на хэширование/сравнение паролей, генерацию и валидацию JWT.
- E2E: регистрация → логин → защищённый эндпоинт с токеном → без токена (401).
