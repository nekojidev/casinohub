# History Service

Read-model для аналитики и экспорта. Заполняется исключительно через RabbitMQ-события, никогда напрямую из других сервисов.

## Конвенции

- Чисто денормализованный слой для чтения — не источник правды ни для чего. Если History упал/отстал, это не должно ломать Wallet/Game.
- Агрегационные запросы — здесь, не в Wallet/Leaderboard, чтобы не грузить критичные для транзакций сервисы.
- Возможна eventual consistency — это нормально, объясняй, а не "чини" синхронностью.

## Тесты

- Consumer корректно строит агрегаты из входящих событий.
- Дублирующееся событие (retry) не искажает агрегат.
